> **Antigravity 原生零 Gemini 模式（2026-11-24）**：本插件默认完全不调用外部 Gemini API（`agent_native.is_native() == True`）。观察、筛查、审片都由当前 Agent 直接使用 `read_file` 看视频/帧板与听音轨完成，结论通过 `--import-nodes` / `--import-verdicts` / `observe --import-obs` / `select --audit` 落盘；下文还提到 Flash、Gemini 的地方是当时的实测记录或用户原话，不是现在的做法；本地听写由 `faster-whisper` 经 ffmpeg 解码执行。

## 对白改词优先“音节数对齐”（2026-11-24 Antigravity 看听优化）

- **适用场景**：**画内可见说话人嘴部**的改词（`on_screen_dialogue`）。
- **核心原则**：Seedance 视频参考模式会强烈跟随 `@视频1` 原说话人的口型开合节拍。原词与新词的音节数差过大时（例如 4 音节 `Lymphoria` 换成 2 音节 `LymphLoop`，或 4 音节 `Stillingia` 换成 2 音节 `Burdock`），首次生成极易出现吞音、卡顿、多念怪音或口型僵硬拉扯。
- **写法规范**：
  1. 品牌名：原词为 4 音节（如 `Lymphoria`）且画内见嘴时，优先改写为 **4 音节的 `Yesnap LymphLoop`**（`yes-nap lymph-loop`）而非 2 音节的 `LymphLoop`；旁白（画外音、不可见嘴）可自由用 `LymphLoop`。
  2. 成分与用法词：优先挑选音节数差 ≤ 1 的等效说法（例如 4 音节 `Stillingia` 优先配 4 音节 `Dandelion` / `Calendula` / `Echinacea`；2 音节 `dropper` 配 2 音节 `packet`）。
  3. 脚本校验：`swap.py generate --prepare-only` 会自动跑 `agent_native.check_dialogue_syllables()`，当画内对白改词音节差 ≥ 2 且占比 ≥ 28%（或 ≥ 3）时在终端给出建议提醒。
  4. **配合人物卡补做**：如果首次生成仍因原口型锚定太强导致念错或口型发僵，第二次补做直接走**人物卡模式 + `# voice:`**，彻底脱离原视频口型束缚。

## 原生看听 6 项结构化审片自检（`select --audit`）

每段生成完成后，**先用 `read_file` 直接看并听生成片 `.mp4`**，再在 `swap.py select` 时传入 `--audit` 记录 6 项核查结论：
- `competitor_clean`：无竞品容器 / 滴管 / 瓶贴 / 品牌词残留
- `front_face_ok`：展示/近景镜头为宽正面（印 LYMPHATIC 的面）朝镜头；纸盒竖着站却半秒以上看不到 LYMPHATIC、只看到竖排手写标志那一面，就是 false
- `scale_ok`：按数字判，不凭感觉——纸盒正面高:宽不超过 1.65（真盒 1.3）、任何一面长:短不超过 2.3（真盒侧面 1.86），没缩成火柴盒；`select` 会自动用 `carton_check.py` 量，量出超线时填 true 也会被拒，必须先 read_file 看并排对照图
- `physics_ok`：物理合理（条包不自站立、不撕包、服用时手中有条包）
- `speech_lip_ok`：已听生成音轨，台词完整、无竞品词或乱码、口型与声音同步
- `text_clean`：无多余字幕、竞品水印或错乱文字

任一项为 `false` 时，`select` 会自动拦截并要求将该镜头写进 `goofs.json` 走 `shot_regen.py round open` 补做（仅交付兜底记录瑕疵时可用 `--allow-audit-fail`）。

## 每镜大小参照（用户 2026-11-25）

用户看完批 62 每个镜头后说：“最大的问题是产品在每个镜头里都是忽大忽小的，非常出戏，一眼假……给九宫格和手持，都不能解决根源问题。人眼看产品到底是偏大还是偏小，基本都是有参照物，例如和人脸的比例，和手的比例，抓握时候手的开合是大还是小……每个生成的镜头，都要去找当下镜头里的某个参照物……这没有一个标准，每个镜头的参照物可能都不一样，但和人脸，和手的参照大概率是最常见的。”

- **为什么要写**：九视图只管正面长什么样，手持图只管握法；模型不知道这一镜里产品该多大，就会照参考片里滴剂瓶的大小画，或者每镜各猜一个大小。用户在批 62 标了 19 段，15 段是大小问题：在脸旁边小得像滴剂瓶，从橱柜里拿出来又大了，同一段前后镜头忽大忽小。其中 5 段已经用人物卡模式补过三四次，仍然不对。所以不挂参考视频也解决不了大小问题。
- **怎么写**：每个出现我方产品的阶段，在“结束时”之前写一句 `大小参照：……`（骨架里已经留好空位）。
  1. 先看原片这一镜的高清单帧，找观众会拿来比大小的东西。**画面里有人脸，先写产品和人脸的比例；再写离产品最近的实际物体**（和产品离镜头差不多远的那个）：握着产品的手（手张开多大），其次是旁边的杯子、手机、水瓶、手表、书。没有固定标准，每镜各找各的。
  2. **参照物不能是竞品**（用户 2026-11-25：“在当前镜头内找参照物不会是拿竞品做参照物吧，要找人脸，找镜头内离产品最近的实际物体做参照物”）：竞品的瓶子、滴管、瓶盖、胶囊、软糖，和任何要移除或替换的东西，在生成画面里都不存在，拿它们比等于让模型照竞品的大小画。也不写“和原片里一样大”“比原来的瓶子大”。首次生成挂着参考视频时最容易犯：原片画面里离产品最近的往往就是竞品本身，要越过它找人脸和手。
  3. 写成看得见的大小关系，不写厘米。
  4. 产品比参照物离镜头明显近或远时，要写出来（如“纸盒在前景，离镜头比她的脸近”），不能硬写成一样大。
  5. 同一段里同一个产品，前后镜头的大小关系必须对得上；【保持一致】写“产品在每一镜里和人脸、手、身边物件的大小关系都一样，不忽大忽小”。
- **首次生成也一样写**（用户 2026-11-25：“能不能把在当前镜头内找参照物描述产品比例的做法也同样放在首次生成里。有总比没有好，毕竟带原视频参考生成出来的才最理想”）：首次生成的骨架（`decide` 填的和 `plan` 出的）同样每个产品阶段留了“大小参照：”。挂参考视频时，模型最容易沿用原片竞品容器的大小和手的张开幅度（批 62 用户原话：“本段全部继承了原滴剂瓶和手部的相对比例”），所以 @视频1 的职责句后面固定接一句“产品的大小不沿用原片里被替换容器的大小和手的张开幅度，按事件脚本里每一镜写的大小参照来画。”（骨架已写好）。写大小参照时按我方产品的真实大小写，不按原片里竞品的大小；原片里手只捏着小滴剂瓶的，写纸盒时要写出手张开到一整掌宽。
- **检查**：`generate --prepare-only`、`shot_regen.py prepare` 和 `round submit` 都会检查（`swap_design.scale_problems`）。有纸盒或条包的阶段没写“大小参照：”，或【保持一致】没写“忽大忽小”，或挂了参考视频而 @视频1 职责句没有“不沿用……”这句，或大小参照里出现竞品、滴剂、滴管、胶囊、原片、原来，以及本段“完全移除原片中的……”清单里的东西，就拒绝。

## 杜绝竞品闪回（用户 2026-11-21："在skill的流程上，怎样才能杜绝这种bug出现"，选"先改切点吸附和终检闪回关"）

## 说话镜头只用自己的声音（用户 2026-11-21："这种带有口型同步的替换段，不论有没有改口播，都应该要用生成段自带的音频"）

查三批成片（2026-11-21）：`select` 自动换原声这三批没触发，问题出在补做拼接。Claude 用 `splice --audio` / `--audio-window` 把首次生成、补镜或原片的声音铺到新拼出来的画面上，59 段里 40 段不是那段画面同一时刻的声音：有的贴到别的画面上（看得到嘴就错位），有的同一个片段的声音和它自己的嘴错开 0.2–1.5 秒（4112589689049500 G03 晚 1.5 秒、3389499438018088 G01 晚 0.24 秒、29775926618681230 G06 早 0.27 秒、1684754143358834 / 1159854673247051 / 1634896741712114 G13 晚 0.2 秒）。

- **规则**：画面里看得到有人说话的地方，声音只能是同一个文件、同一时刻的自带声音，不论台词改没改。原片声音、首次生成的声音、借来的词只能放在看不到嘴的画面上。
- **`select`**：不再自动换原片声音；`--sound source` 用在有画内对白的段要加 `--no-mouth`（看过整段，没有说话的嘴）。`sound_drift` 只是台词相对原片的时间变化，回执里叫 `sound_note`，不是口型检查。
- **`splice`**：算出新片里每一段声音是不是那段画面同一来源、同一时刻的（同一文件的加字幕 / 去字幕版本算同一来源，误差 1.5 帧以内；放慢的镜头、末帧定格下面铺的声音都算外来）。外来声音的地方必须被 `--no-mouth A-B`（新片的秒数，agent 看过那里没有说话的嘴）盖住，否则拒绝并列出时间。账本记 `foreign_sound` 和 `no_mouth`。
- **`shot_regen.py splice`**：原速镜头一律带自己的声音；放慢的镜头自动标 `--no-mouth`；`--source-sound` 只对放慢的镜头有效。
- **生成的声音和它自己的嘴对不上**：是穿帮，补做那一镜（`lip_sync`），不换声音、不做本地口型对齐。
- **消音窗口里新词没说出来**：画内对白不借词，补做那一镜（`lip_sync`，台词写全）；旁白 / 画外可以借同一音色的词（`--no-mouth` 标出那一截）。

## 去字幕缓存（用户 2026-11-21："现在这个流程中，参考片去字幕是不是最费CPU的环节"，"先做缓存"）

- 实测：去字幕每修一帧约 4.5 核心·秒（LaMa 512×512，1.15 秒 × 4 线程），三批平均每条片修约 2,000 帧，约 9,000 核心·秒，是全流程最费 CPU 的一环（整片编码每次 400–560、本地听写每条片 1,000–1,500）。三批目录里有 1,066 个去过字幕的视频，在用的参考片只有 395 个：大量是重做参考片、补做镜头、复用片时重复修同样的帧。
- `caption_lama.py` 现在按"送进模型的 512×512 画面块 + 遮罩 + 模型版本"做键缓存修补结果：同样的块再修时直接取结果，不跑模型，结果逐像素相同。只存能落回画面的部分（遮罩外框 + 16 px，无损 PNG，每块约 47 KB）。
- 位置 `~/.cache/lymphloop-models/lama-cache/`，两份 skill、所有 RUN 共用；超过 `LYMPHLOOP_LAMA_CACHE_GB`（默认 12 GB）按最久没用的先删到 80%；`LYMPHLOOP_LAMA_CACHE=0` 关掉。去字幕回执里 `lama_cache` 记命中和未命中块数。

## 成片按内容缓存（用户 2026-11-22："顺剪有个问题，只要中间有一个镜头穿帮，回剪之后所有的镜头流程都要从头来过"，"改，按内容缓存"）

- 问题不在顺剪，在缓存的钥匙：`recut` 每块的缓存按整张剪辑单算，改一个镜头所有块作废、整条重编（2,000–3,000 核心·秒）；`brand` 把整条片解码、crf 12 再编一遍；`final-screen` 每轮重查全部生成段、重出全部闪回帧板。
- **回剪**：每块（一段原片或一个生成画面）单独编码，钥匙是它是什么——文件字节、取的帧或秒、输出帧率和画幅、编码代码，不含它在成片里的位置（`media_pipeline.atom_key`，文件在 `RUN/recut/render/atoms/`，保留最近 3 次回剪用到的块）。补一个镜头只重编这一块，后面的块原样拿来，按新位置无损拼接。所有块用 x264 `stitchable=1`，不同时间、不同 crf 编出来的块头信息一致，拼接安全。
- **盖水印**：按块盖（`watermark_brand.stamp_atoms`）。块里没有水印帧就直接用回剪的块，不重编；有水印帧的块盖好单独编码（crf 12），钥匙是块的内容 + 这一块上盖的字（相对块开头的帧号、框、方向）+ 盖字代码，缓存在 `RUN/recut/brand-atoms/`。回执 `by_atom` 记这次盖了几块、复用几块、几块没动。旧 RUN 的时间轴没有块钥匙时照旧整条盖。
- **终检**：每次把成片每块的内容签名写进 `final/<sha>/content.json`；下一轮和上一次终检的成片比，只查新内容（`final/<sha>/baseline.json`）。上次有未了结问题的块（筛查标记 / 拿不准 / 出错的镜头、水印残留、听到竞品词、闪回 hit）即使没变也重查；上一版没跑 `flashback-review` 时闪回帧板照旧出全部生成段。没变的块是同样的画面和声音、只是换了位置，上次已经筛过、看过。`--no-baseline` 或 `--full` 关掉。整条成片的水印模板比对照旧每轮读全片（约 30 秒）。
- 对比看板和已知问题里的新时间码都从 `master.mp4.timeline.json` 换算；顺剪后时间码变了是正常的，先换算再写。
- 第一次用新代码回剪的 RUN 会把所有块重编一次（钥匙变了），之后才省。

## 补穿帮一轮一批（用户 2026-11-22："补穿帮一轮一批"）

三批 26 条（11-20/21）实测：11 条付费片首次 146 段、612 个镜头，单镜头补做 145 次（$90.5，占花费 29%），47% 的段至少补一次。同样十来次补做，3389 集中在 12 分钟内提交、1506806 在 24 分钟内；1506620 拖 6.3 小时、1812 拖 3.3 小时——发现一处做一处，每处都要等约 7 分钟生成、再跑一遍收尾。

- **先审完所有段**，把整条片的穿帮列成一张清单，再动手。清单 `goofs.json`：`[{"seg": "G05", "at": "3.2", "why": "competitor", "note": "台面左侧旧瓶还在"}]`，`at` 是生成片里的秒数（或 `起-止`）；可选 `from_s` / `to_s`（缩到单个动作）、`source_s`（原片参考里这一镜的秒数，切点错位时用，见下）、`no_mouth`、`no_cut`、`mute`（看得到嘴且有改词时，参考片里旧词的秒数）、`name`。也可以用 `--goof G05@3.2:competitor:说明` 逐条给。
- `shot_regen.py round open --run RUN --file goofs.json`：每处自动 `locate`（镜像、台词、声音方式）+ `ref`（放慢 / 原速按规则自动选），写帧条和提示词，登记原因，记进 `shots-regen/rounds/round-N.json`。**11-23 起默认人物卡模式，见下一节；这里说的参考片骨架只在 `--mode reference` 时用。** **提示词骨架取这一段已写好的提示词，只留这一镜的阶段**（场景、人物、音色、图的职责都是写好的），开头注释里写着登记的穿帮；这一镜要的图和整段不一样时退回设计表骨架。超过同一处三次、或没比上次窄的，标 `blocked`，不用写，进交付说明。
- **原片窗口对不对，看 strip 判**：`locate` 默认按"生成片跟原片同一秒"找原片镜头。生成片少了或多了一个切点时，镜头已经错位（11-22 片 1659373095741717 G01：生成片漏掉原片 1.97 秒的切点，生成的女侦探近景 5.79–8.04 秒其实是原片 S025 的 3.97–5.83 秒，按同一秒会对到男侦探的 S026）。切点对不上时 `round open` / `locate` 每处都带 `timing_warning`；看 strip 首末帧和原片帧板，对错了就在 goofs 里给 `"source_s": "起-止"`（原片参考里这一镜的秒数，`locate --source-window` 同义），再 `round open`。补做盖回的帧（`base_frames`）不变，只换参考片取哪一段。
- 改完每个 `shots-regen/NAME.txt`（只改针对穿帮的那几句，【生成目标】【主体与关系】改成只说这一镜）。
- `shot_regen.py round submit --run RUN`（后台跑）：全部提示词过检查才一次提交，有一个不过就全不交、列出每个的问题（一轮只等一次；`--partial` 先交通过的）。下载后每处出 `NAME.result.png`（上排参考、下排生成）。中断后重跑同一命令只续查，不重复提交。
- 看每张 result：登记的穿帮没了、没有新穿帮。`shot_regen.py round splice --run RUN [--drop 仍有穿帮的NAME …]`：同一段的所有补做镜头一次拼回（各自盖住自己的帧，说话镜头带自己的声音，放慢的镜头自动标 `--no-mouth`），自动 `select`；`--finish` 接着跑收尾。选用片在 open 之后变过的段会拒绝（帧号作废，重新 open）。
- `--drop` 的进下一轮，范围缩到单个动作；同一处最多三轮（原规则不变）。
- **每次补做都登记原因**（八类，同 qa-checklist 穿帮清单）：单处手工 `prepare --goof` 也必须带 `--why … --note …`。批次做完跑 `shot_regen.py reasons RUN1 RUN2 …` 看各类次数：哪一类多，就去改规则表或提示词写法，让首次生成不再出这类穿帮。之前 145 次补做没有任何原因记录，只能从任务名猜。
- 配套：`captions` 只重做选用片、台词或样式变了的段；`recut` / `brand` / `final-screen` 按内容只处理变了的块（见上一节）。

## 补做一律用人物卡模式（用户 2026-11-23："第一次生成采用原片参考的模式，如果第一次出现穿帮了，第二次补生就要采用人物卡模式"）

**第一次生成**（每段的 a1）照旧：原片参考视频 + 产品图 + 五段式。**审片发现穿帮后的每一次补做**（第一轮及以后各轮）都改用人物卡模式：不挂参考视频，只挂这一镜里出现的人物卡、设计表给的产品图，说话镜头再挂说话人自己的一段声音作音色参考；场景、光线、机位景别、人物左右站位、手里拿什么怎么拿、台词，全部写进提示词。理由是视频参考会照抄原片的动作和容器轮廓（滴管仰头、抛瓶、窄瓶身被画成细长纸盒），补做时再挂同一段参考片，同样的穿帮会再来。

实测（11-23，片 1603578481269031 G01 的三个穿帮镜头，被 1106、1430 共用）：
- **原来的穿帮**：纸盒抛在空中、近景把纸盒侧面当正面、过肩镜头纸盒像长条。
- **怎么生成**：两张人物卡 + carton_views + carton_hand + 灰须男子 8.6 秒原声，seedance-2.0 720p 8 秒，$1.02，一次生成。
- **结果**：三句台词全中，纸盒一直在胖男子手里，正面朝镜头，比例对；接回成片后用户看过对比片说“可以，就这样”。
- **代价**：新镜头灯光比相邻镜头略亮略冷；人是按卡生成的近似长相，不是原演员本人。用户接受。

做法：
1. **出人物卡**（一条片做一次，各轮共用）：写 `RUN/cards/cast.json`，每个出现在补做镜头里的人写一条。
   - `identity`：英文，**体重、肚子量化写在最前**，否则会被画瘦。
   - `outfit`：照原片这场戏的衣服。
   - `srcs`：**整条片里**这个人最清楚的正脸，不限补做的那一段，最多 3 张。写原片秒数，`crop` 用比例坐标裁掉字幕行和别人。
   - 然后跑 `shot_regen.py cards build --run RUN`：nano-banana-pro 4:3 2K，每张约 $0.1。出来的卡要亲自看：脸像不像、胖瘦对不对，不对就改 cast.json 再 `--force --only ID`。长得像明星的卡会被视频模型的审核拒绝，换别的原片截图重出。人物卡不受“一次付费”限制。
2. **`round open` 默认就是人物卡模式**（`--mode reference` 或单条 `"mode": "reference"` 只在用户点名要旧做法时用）。
   - 每处照样 `locate`，得到盖回帧号、台词、声音方式。
   - 原片这一镜原速裁出来（左右按生成片镜像），只给 agent 看帧条、给 result.png 作对照，不上传。
   - 写好人物卡模式的提示词骨架，开头三行：
     - `# cards: ID,ID`：这一镜出现的人物卡，按顺序就是 @图片1、@图片2……
     - `# views:`：设计表给的产品图，接在人物卡后面编号。
     - `# voice: A-B`：只有看得到有人说话的镜头才有这一行。选用片里只有这个说话人开口的 2–15 秒，作 @音频1 的音色参考；台词以提示词为准。
3. **写提示词**：五段式，正文里不出现 @视频。没有参考视频时，房间、机位、声音只存在于文字里，所以写法照 ai-drama-ad 的 `references/prompting.md`（用户 2026-11-24：“本质上都是在用人物卡和产品参考在塑造当前场景”）。区别只有一点：这里是**还原原片**，环境和机位照原片这一镜和前后相邻的原片镜头写，补出来的镜头要接得上，不去场景库另找地点。
   - **环境只用文字，不挂场景图**（用户 2026-11-23）。`# cards` 只写 cast.json 里的人物，`prepare` 会拒绝别的图。【主体与关系】按这个顺序写：
     1. 时间和光：光从哪来、冷暖。
     2. 3–6 个固定物件和它们的相对位置。
     3. 一句轴线锚点：人相对物件的朝向，如“坐在长凳上、背对储物柜时，门在右手边”。
     4. 每个人相对固定物件的位置、坐着还是站着、朝向谁。
     5. 机位表：每个机位写架在哪、朝哪拍、拍谁、**背景永远是什么**，再写一句某个固定物件在镜头的哪只手边。原片这一段只有一个机位就只写机位 A。
     6. 产品的初始状态和数量：在谁手里或放在哪、密封还是已开、哪一面朝镜头。
     7. 说话镜头在末尾写音色句，七样写满：人种与口音、性别和年龄档、音高、质感、语速与节奏、习惯、一句“不是什么”（如“不是播音腔”）。音色句和 @音频1 一起给。
   - **不新加切刀**：原片这一段有几镜就写几个阶段，每个阶段点名用哪个机位（用户 11-23 嫌 1912 那段“非常碎片化”）。ai-drama-ad 的“两秒一刀、句中切刀”是给整场戏用的，补做不用。
   - **每个阶段写身体在做什么**：说话的人说这句时身体怎么动，听者写闭着嘴的具体反应（嘴抿成一条线、眉头一挑），表演幅度照原片，不默认写成“平静”。写大动作，不写形容词。
   - **台词**：照常写成 `{原词}`。一句话可以按情绪节拍拆开写；括号里写听得见的东西：语速、停顿、重音、音量。说话前写触发动作，`}` 后面只接动作，不接语气。画外音的镜头写“画外传来说话声，画面里的人闭着嘴”。
   - **产品**：每阶段以终态句收尾，写清产品在谁手里、数量。原片是递交、抛接这类容易穿帮的动作时，可以改成产品从第一帧起就在接的人手里（跨镜省略），少一个穿帮机会。穿帮那一处直接写成正确的样子。
   - **【保持一致】**写：
     - 环境、光线、站位和机位同上，镜头之间空间方向稳定；
     - 产品、桌面和手与人物同一种画面质感；
     - 说话镜头再写：不说话的人闭着嘴做自己的反应（自然闭口），只有写明台词的人张嘴说话。
   - `round open` 写出的骨架已经按这个顺序排好。`prepare` 少了以下任一项就拒绝：机位表、“手边”、“空间方向稳定”、“画面质感”，或说话镜头的音色句。
4. **提交和检查**：`round submit` 和以前一样。`prepare` 会检查四件事：
   - 人物卡都已出好；
   - 每张图、@音频1 都有自己的职责句，正文里没有 @视频；
   - 说话镜头有 `# voice:`；
   - 同一处补做次数（最多三次、后一次要更窄）照旧。

   任务是 `generation_mode: cards`，接口参数 9:16、720p、时长都照旧。时长取这一镜整秒（说话的再加 1 秒），4–15 秒。声音片段经全机共享托管发布，APIMART 没有音频上传接口。
5. **拼回**：`round splice` 照旧。
   - 说话的镜头原速接回、带自己的声音，长度到台词说完，不短于原镜头。
   - 没人开口的镜头取前“原镜头长度”秒，盖住原来的帧，下面铺这一段原来的声音（自动标 `--no-mouth`）。
   - 定格帧照旧在 finish 的 retrim 裁掉。

## 跨 RUN 共用结果（用户 2026-11-22；Claude 新批次："尚未找到跨 RUN 导入共用结果的命令"）

上一批 26 条里只有 11 条付费生成，15 条是同一组画面的改版（换开头、换结尾、重新上传），靠手工把代表片的结果搬过去。现在是命令：

- **顺序**：每组画面相同的片子挑一条代表片，完整做完（终检、看过闪回帧板）。其余片子照常做到 `plan`（识别、切段不能省：改版的开头结尾是它自己的内容），然后
  `swap.py reuse --run 这条片RUN --from 代表片RUN --dry-run` 看报告，再去掉 `--dry-run` 正式跑。
- **怎么比**（`scripts/reuse.py`）：两条片每帧缩成 18×32 的灰度小图。代表片每个生成段取 5 个锚点帧在这条片里找候选位置，再整段逐帧核对同一个帧差。2026-11-22 在新批次 5 条片上实测：同一帧不同编码的差值平均 0.1–0.4、最大 1.1，别的画面 21–36；1106373148453803 和 1430249255980902 除了开头 302 帧（约 10 秒）全片逐帧相同，2078981646837840 和 2836804316692183 开头不同、之后差 25 帧。判定线贴着编码噪声定（平均 1.5、最大 5，98% 的帧达标）：同一个机位晚一秒的画面只差几个单位，放宽会把代表片的片段放错时刻。重编码很重、差值偏大的片子才加 `--tolerance 2`，并逐个看共用段的接缝。
- **导入什么**：代表片那一段的选用片（含去字幕 / 加字幕版本）、`clip_in/clip_out`、字幕记录、瑕疵记录、看板备注、提示词（看板显示用），成为这条片的 `G9nn`（`plan/segments.json → reused_segments`，账本 `provider: reused_generation`，费用 0，`reused_from` 记代表片、段、帧差和比对数值；代表片的拼接点 `joins` 一起带过来，闪回关照常取点）。
- **这条片自己的计划段**：整段都是代表片里有的画面（代表片重做的部分 + 代表片留作原片的部分）就撤下（`dropped_for_reuse`，报告 `set_aside` 里列出代表片留作原片的秒数，看一眼）；含代表片里没有的画面、已经在这条片里生成过、或跨两条代表片的，留下照常生成（`kept` 写明原因），和它重叠的代表片段不导入。计划里没有、代表片却换了的画面也照代表片导入。
- **不共用的情况**（`notes`）：帧率不同；代表片那段保留了原画面（没有生成结果：这条片照它 `select --keep-source-picture`，成片上的定点修补再做一遍）；这条片里没有那段画面或只有一部分。
- **之后**：`generate` 只处理 `segments` 里剩下的段；`captions` 不碰共用段；`recut` / `brand` / `final-screen` / 看板包含共用段（看板标“共用结果”）。共用段和这条片自己画面的接缝是新的，闪回帧板逐张看。
- **共用段有穿帮**：回代表片的 RUN 修（`round`），修完在这条片重跑同一条 `reuse`（每次先撤掉上一次的导入再从头算）。在这条片里对共用段 `shot_regen locate` 会拒绝并提示。
- 代表片没做完时默认拒绝（`--unfinished-donor` 可以先用它当前的选片，之后必须重跑）。
- 没做的：改版片仍要自己跑识别和切段；“和代表片逐帧相同的部分直接继承识别结论、只识别独有部分”还没做。

## 生成段不留定格画面（用户 11-22："生成段的最后都会被定格一下，比成了静态帧停顿了一秒多"）

参考片要补到整数秒（最少 4 秒），补的部分是末帧定住；模型照着生成，片尾出现 0.3–2 秒静止画面。11-22 实测已交付 17 条里 16 条有：段尾 33 处，补做镜头拼进段中 12 处，其中约一半声音还在说话。

- `select` 自动量片尾静止画面（`media_pipeline.frozen_tail`），超出本段原长的静止部分直接裁掉（不低于原段长度）。静止处还在说话（逐词听写，不看响度）就保留到话说完、记缺陷 `frozen_tail_speech`，这一镜下一轮按 speech 补做；只压住最后一个音节（≤0.3 秒）的直接在话后裁。确实是原片静止镜头（片尾卡等）要保留时用 `--keep-frozen-tail`。
- 补穿帮拼回（round splice）时，原速补做镜头的长度不超过它画面定住的地方（不低于原镜头长度），除非那里还在说话。
- **回剪时一律裁掉定格帧**（用户 11-23：“不要用真实画面补满4秒，回剪的时候把定格帧裁掉”）：`finish.py` 第一步 `shot_regen.py retrim --run RUN --all`，每段选片里补做镜头的定住帧和超出原段长的段尾静止都裁掉，没得裁的段不动；改了段就重做字幕。`recut` 前查同一件事（`swap.still_left`），还有定格帧就拒绝并列出段号。原片本来就静止的镜头（片尾卡）select 加 `--keep-frozen-tail`，记在选片里，retrim 和 recut 都放过。共用段跟代表片走：代表片 finish 后在共用片重跑 `reuse`。参考片补满 4 秒的方式不改（末帧定住），不用真实画面续接。11-23 拿 2896 试跑（未改）：G01 1.9 秒、G05 2.6 秒、G04 0.3 秒定格会被裁。
- 已交付的片子：`shot_regen.py retrim --run RUN --seg G##` 或 `--all`（可先 `--dry-run`）。选用的是拼接就从这个拼接本身去掉补做镜头的定住帧（原生 splice，画面和声音一起），再 select；不是拼接就用原窗口重新 select。免费。然后 `finish.py --from captions`，共用片在代表片之后重跑 `swap.py reuse`。
- 补到整数秒的方式没改：试过把最后一个镜头放慢补满，但会让段内原有的那部分也变慢，违反原速，已退回。
- **"定住"包括缓慢漂移的静止**（用户 11-23 看 2114 G03："几个镜头链接处还是觉得有定格帧"）：补做镜头的定格常常不是一模一样的帧，而是画面还在极轻微地漂（相邻帧差 0.03–0.25，正常说话是 0.3–2.4）。原来用 ffmpeg freezedetect 跟定格起点那一帧比，漂移一累积就超出容差，只裁掉了最后完全相同的那几帧：2114 G03 两个补做镜头在接点前各留了 1.4 秒和 1.7 秒近乎静止的画面，抽帧看不出，肉眼一看就是定格。`frozen_tail` 现在同时量相邻帧差（180×320 灰度，0.25 秒窗口均值低于 0.3 算静止）和 freezedetect，取更早的那个起点；`select`、`splice --into`、`round splice`、`retrim` 都用它。抽查 4 个原速补做镜头，静止起点和原片镜长几乎一致（1.96/1.96、1.38/1.37、2.88/2.90），说明补做镜头过了原片镜长基本都是定住的；9 条整段生成的段尾只往前多出 0.25–0.45 秒。裁剪的两道保护不变：不短于原镜头（原段）长度，还在说话就不裁。已交付片子用 `retrim` 重新处理即可。

## 批次运行经验（11-22/23 三线程 25 条，监工总结）

本批：25 条（13 条是共用片，零生成费）、$283.36；首次生成 124 段，补做 158 次（competitor 61、physics 39、speech 36、identity 7、side 6、count 5、shape 4）；补满三次的 15 处交用户一次裁定。从开跑到全部交付约 22 小时，其中好几个小时是线程停着等维护者修母版。下一批拿这些数对比。

- **报了母版问题，不要整批停下等**。线程 3 报了问题后整条停住，只交了 3/9 条，是用户先发现的。正确做法：问题写进本批的维护者记录（复现命令 + 报错原文，用 `skill-run` 原命令），被卡住的那一段或那一步先放着，其余段、其余片子照常推进到交付。母版修好后直接用新脚本续跑原命令，不用再等确认。
- **补满三次的不问、不停**：照常 `finish` 交付，记进已知问题。全批交付时出一张汇总清单，每处写：片子、段、成片时间码、穿帮、已补次数、建议改法、估价、共用片里同一处的时间码。用户一次性裁定后再动（见上一节）。
- **自动检查中途断了，用原命令续跑**（117 终检遇到 `Google transport interrupted (URLError)`）：缓存会接着用，不改观察结果。自动检查失败时，不能拿自己看帧板的结论顶替它，必须重跑到 `errors=[]`。
- **Gemini 返回 429 先看 quotaId**（只在打开外部 Gemini 时会遇到）：`FileStorageBytesPerProject` 是 Files 库满了（20 GiB 上限，本批一度积到 18,694 个文件、21.5 GB），不是限流，等多久都没用。`google_api.py prune-files --hours 3` 删除 3 小时前上传的临时副本（本批删了 17,779 个，腾出 21 GB）。删除远端文件要用户同意；`LYMPHLOOP_GEMINI_AUTO_PRUNE=1` 是满了自动清，默认关闭。≤8 MB 的媒体直接内联发送，不进 Files 库。
- **参数单位看 `--help`**：`flashback-review --hit` 填成片帧号（`4142-4182`），不是秒数；传秒数会报 `invalid literal for int()`。
- **用户看片发现、自动检查没抓到的**：段尾定格，现由 `select` 自动裁掉，已交付的片子用 `retrim` 处理。交付前仍要在每个生成段的段尾和补做镜头的尾巴上抽查一次（`media_pipeline.frozen_tail`，会抓缓慢漂移的静止）。retrim 之后剩下的 0.3–0.9 秒静止只要在原段长度以内（原片本来就不动的成分特写、静态展示）就不用再裁，再裁成片就比原片短了。
