### 片源规则

1. **直接从原始源文件按时间裁**（用户 2026-10-23）。段的起止帧在整数帧率网格上，换成秒后直接在 `state.json → source` 那个原文件上取，不经过 `master-cfr.mp4`，也不经过去水印母版。
2. **只编码一次。** Lanczos 放大 + libx264 CRF 12、限码率按段长定（`swap.ref_maxrate`：整个文件不超过约 2.2 MB；APIMART 下载参考片 60 秒没下完就断开）。去字幕和去水印在同一次编码里完成：帧从源文件解出、修补后直接编码。
3. **送模型的片源放大到 720P**：短边低于 720 的升到 720；已经不低于 720 的不缩放。帧率不低于 24。
4. **输出 480p、9:16、整数秒**：`duration` = 段长向上取整（最少 4 秒，接口下限；本 skill 的段不超过 15 秒）。11.83 秒的段生成 12 秒。
5. **参考片和输出一样长**：末帧定住、声音补静音，补到这个整数秒。选片时默认只取本段自己的长度（`select` 不写 `--clip-out` 时取段长），补出来的那一小截不进成片。
6. **去字幕、去水印**（`scripts/caption_lama.py`，LaMa 修补模型）。逐帧 OCR 找出字幕行，把**整行文字框**（外扩盖住描边和投影）交给 LaMa 重建后面的画面；漂浮水印的框来自 `RUN/watermark/scan.json`，再加上对参考片四边的一次补扫（淡的竖排水印母版扫描可能读不到）。模型文件 208 MB，第一次用时自动下载到 `~/.cache/lymphloop-models/`，两份 skill 共用。12 秒的段约 3 分钟（CPU）。
   - 2026-11-11 在 Lymphoria G03 上对比过三种去法：OpenCV 涂抹（11-10 的做法）在纹理面和边缘留一片柔化痕迹；LaMa + 紧贴字形的遮罩会留下字形状的杂纹；LaMa + 整行文字框补回了衣服纹理、手和木桩，看不出痕迹。所以遮罩用整行框。
   - 同一帧里相距远的区域（下方的字幕和角上的水印）各用一个修补窗口；窗口最大是画面短边，一个窗口盖不住的部分以前会原样留下。
   - 字幕框在 OCR 读到它的前后各保留 3 帧，只在同一个镜头内保留。水印扫描里前后补出来的框，只保留不在字幕位置、且不比水印字粗的：瓶标上的品牌字也会被水印扫描记下，它补出来的框落到下一个镜头会把那里的手臂抹掉。
   - 画面中部的横排文字都按字幕行处理，竞品瓶标上的字也会被抹掉，这不影响生成。
   - 清完后用 OCR 复扫一遍：原字幕位置仍读得出字的帧超过 2% 就报错停下（`caption_clean.frames_left`）。
   - 准备完必须打开 `upload_video` 的帧板亲自看：没有字幕、没有水印、修补处看不出痕迹，人物的手和脸完整。字幕压在产品或脸上的镜头、每个镜头的头几帧重点看。
7. **首尾不带邻镜头的帧**（`swap.edge_trim`）。23.976 / 29.97 帧的片源按时间裁，窗口可能晚一帧开始、多带一两帧下一个镜头（2026-11-11 Lymphoria G03：结尾两帧是下一场的浴室，补尾又把它定住）。准备时自动检查首尾 3 帧里的硬切并裁掉，裁完再核对一次，不干净就报错。

## 2. 写之前先看清楚

1. 看 `RUN/shots/sheets` 里这一段的帧板，按镜头列出：人物、站位、谁在说话、产品在哪只手、产品此刻的状态。
2. 用 `shots.py frames` 按每秒 4 帧导出，再把每个镜头里拿产品的手放大到全分辨率看。竞品经常只露一部分：瓶盖、瓶颈、滴管胶头、罐口、一角标签、掌心的一粒胶囊、指尖的一颗软糖、勺里的粉、前景虚焦的手里横握的瓶子、远景里很小的一只瓶子、镜子里的倒影。对照 `RUN/detect/competitor.json` 的 `hard_cases` 和锚点帧逐镜头找。**每一处都要在对应镜头里写成目标产品**（参考片里竞品还在，漏写的地方模型会照着参考片画出来）：11-10 那条有 3 段因为只写了手里那一瓶，台面上的第二只瓶子原样留在成片里。
3. 记下哪些镜头根本看不到产品。这些镜头在提示词里只写画面里有谁、在做什么；产品只出现在写到它的镜头里（否定句对画面无效，见 §3 第 1 条）。
4. 对照 `segments.json` 里这一段的 `speech`（整句与时间）和识别给出的改词，判断台词有没有冲突。冲突只有四类：产品名、剂型（drops、dropper、capsules、softgels、pills、gummies、powder、scoop）、用量用法（half a dropper、under your tongue、two capsules a day、chew two gummies、one scoop in water）、成分。**成分冲突只指点名的具体成分不在我的产品里**（以 `profile.json → facts.ingredients_printed_front` 为准：Cleavers、Burdock Root、Dandelion、Bromelain、Echinacea、Calendula、Red Clover；例如 Stillingia → Burdock Root、Prickly ash → Dandelion），这时成分口播和成分画面一起改。草药数量（four herbs / 12 herbs）、泛泛的功效说法（drain the fluid、support lymphatic drainage）都不算冲突，一字不改（用户 2026-10-24 定）。讲服用时间、和别的补剂一起吃之类的台词也不冲突。`merge` 会自动把 Pro 改掉的草药数量改回原文；其他不该改的改写，在 `detect/overrides.json` 里给该镜头写 `"rewrites"` 覆盖。
5. **原片和 LymphLoop 不是同一个品类时**（少见；用户 2026-11-11：例如讲肉桂和血糖的 Metabolae），凡是和 yesnap LymphLoop 矛盾的元素全部改掉：点名的成分换成 LymphLoop 自己的成分，成分画面、包装图上的功效徽章、片尾卖点一起换；改后的机制讲不讲得通不用管。泛泛的、不矛盾的话照旧不动。

## 3. 官方写法与模板

### 写法（每条都对应官方指南里的一条）

1. **只写正向描述。** 写画面里是什么、人在做什么，不写“不要什么”。否定句只在两处有效：字幕（“不要字幕”）和音频（“不要背景音乐”）。`generate --prepare-only` 会检查，含画面否定句的稿子被拒绝并列出句子。改写对照：

   | 想防止的事 | 正向写法 |
   |---|---|
   | 条包自己立着 | 条包平躺在台面上，正面标签朝上，下面有接触阴影（或：斜靠在旁边的罐子上） |
   | 张嘴、伸舌、往嘴里滴 | 合拢的双唇轻抿已开条包的袋口，袋身被指尖轻轻压扁 |
   | 没有产品的镜头被加进产品 | 只写这个镜头里有谁、在做什么：黄色上衣男士脸部特写，皱眉听着 |
   | 纸盒变成薄卡片、火柴盒、细长条 | 纸盒正面约一只成年人手掌宽、略高于宽，侧面厚度约为正面宽度的七成，整只盒子平托在掌心 |
   | 画面里出现撕条包 | 镜头切换后，他手里是顶端已经撕开的条包 |
   | 产品被复制成好几个 | 台面中央立着一个纸盒；条包始终是同一支，只出现在写到它的镜头里 |
   | 旧容器残留 | 参考片里竞品出现的每一处，在对应镜头里都写成目标产品是什么、在哪、怎么拿 |

2. **时间戳用整数秒。** 写“镜头 N（a–b 秒）”，a、b 是整数；有小数的向上取整（0.00–0.87 → 0–1，4.21 → 5）。模板已经按这个规则填好，手写的小数在提交时也会被自动取整。只写“镜头 N”不带时间也可以。一个时间段里只写一件主要的事，写多了会被剪碎或漏掉。
3. **参考片已经给出的只做指代。** 场景、人物、机位、动作在 `@视频1` 里都有，镜头描述一句话就够；笔墨花在产品上：是什么、在哪只手、怎么拿、做什么。同一个人的外貌和服装只在素材说明里写一次，不在每个镜头里重复。
4. **不写编辑类的词。** “编辑、替换、修改、删除、增加、改成”会让任务被判成视频编辑。写成“手里拿的是 @图片1 的条包”。首句末尾加一句 `请注意这不是视频编辑。`
5. **台词写成“称呼台词：“英文””**，放在它开始的那个镜头后面，每句只写一次，后面不跟语气、表情、动作描述（那样会诱发字幕）。画外说的写“画外某某台词”。结尾写“台词使用英语，口型与台词同步，每个说话人的音色与@视频1一致”。细则见 §5。
6. **一次生成只做一件事。** 官方：一次承担多项参考和编辑要求时效果不稳定。字幕、水印、消音都在本地做完，提示词只管“这段画面里的产品是什么”和台词。
7. **数量写成“只出现在写到它的镜头里”**，不写“全片恰好一个”（那样模型会把产品塞进没有它的镜头）。
8. **正文里不写参数**（分辨率、时长、画幅由 `generate` 传），不写理由和说明。

### 模板

```text
严格参考@视频1的场景、人物外貌与服装、站位、机位、镜头顺序、动作和节奏，生成一段 <N> 个镜头的<一句话：什么人在哪做什么>视频，镜头顺序与@视频1保持一致。<人物>手里拿的是@图片1的<青绿色条包 / 已开条包 / 青绿色纸盒>。请注意这不是视频编辑。

@视频1：用于<场景>，<人物>的外貌、服装和站位，机位、景别、镜头顺序、动作、节奏，以及每个说话人各自的音色和背景声。
@图片1：用于<产品>的外观，<结构、颜色、正面印刷>，以及它<捏在手指间 / 托在掌心>的大小。<产品>始终是同一<支 / 个>，只出现在下面写到它的镜头里。

镜头1（0–2 秒）：<谁，景别>，<哪只手怎么拿着产品，做什么>。<称呼>台词：“<英文>”
镜头2（2–5 秒）：<……>
镜头3（5–7 秒）：<没有产品的镜头只写人物和动作>。画外<称呼>台词：“<英文>”

台词使用英语，口型与台词同步，每个说话人的音色与@视频1一致。<一句画面质感和光线>。不要字幕。
```

`plan` 生成的 `RUN/prompts/G##-a1.txt` 已按这个结构预填了镜头的整数秒时间窗、每句台词（改词已替换）和输出秒数，Claude 把所有【写…】换成具体内容后才能提交；留着【写 的稿子、含画面否定句的稿子 `generate` 都会拒绝。实际提交过的例子：`assets/prompts/reference-example-g03.txt`。

## 4. 先定产品形态，再写动作（物理优先）

映射表穷举不完。大量跑片时，会遇到映射表里没有的原片动作。每一段要重新设计动作时，先回答"这个动作在现实里用哪种形态能自然做到"，再动笔。**绝不选一个超出物理规律的方案去迁就原片动作**：那会让产品弯折、拉长、悬空、穿手，也就是严重变形。

### 4.1 两种形态在现实里是什么

| | 条包（未开 `handheld_photo`，已开 `opened_packet_hand`） | 盒装（`carton_views` + `carton_hand`） |
|---|---|---|
| 材质 | 软、扁、薄的铝塑膜袋，装液体 | 硬纸盒，直角直边，翻盖 |
| 尺寸 | 约一根食指长，比拇指指腹略宽，很薄 | 正面略高于宽，一只成年人手刚好托住或握住侧面 |
| 能不能立 | 不能，只能平躺、被拿着或靠在硬物上 | 能，底面着地立在桌上 |
| 怎么拿 | 指尖轻捏边缘或两端；袋身随手指微弯 | 单手握住两个侧面，拇指在一侧边、四指在另一侧；或托在掌心 |
| 能做的动作 | 捏着讲话、展示标签、轻轻晃一下给镜头看、从口袋或包里抽出、（已开条包）闭唇轻抿、（已开条包）挤进一小杯水、平放在桌上 | 立在桌上陈列、正面朝镜头展示、转动看侧面、从购物袋或架子上拿起、放下、翻开顶盖、从盒里抽出一支条包 |
| 绝对不能 | 在画面里被撕开、自己立着、卷起、折成两半、被攥成一团、被环抱、被拧、像滴管一样一滴一滴滴出、未开就出液、比手还大 | 被捏扁、弯曲、单指捏起、塞进小口袋、拿到嘴边喝、盒面印刷扭曲 |

### 4.2 判断顺序（每段都过一遍）

1. **原片这只手在做什么？** 拿着讲话、展示标签、放下或立在桌上、拧盖或打开、往嘴里或舌下滴、把胶囊倒在掌心、把胶囊或软糖放进嘴里、舀粉倒进杯里、从某处拿出、递给别人。
2. **哪种形态在现实里做这个动作最自然？** 按 4.1 表选：
   - 立在桌上或台面陈列、产品主镜头、整只手掌握住瓶身展示、手里转着看角度、多瓶陈列：**盒装**。
   - 入口、**指尖捏着瓶颈、细瓶身、单颗胶囊或软糖**（展示或讲话都算）、掌心托着散粒、从口袋或小包里抽出、往杯里倒：**条包**。
   - 两者都说得通时，选**和原物体大小、握法、手的运动轨迹更接近**的那个。参考片给的是原片的动作：轨迹差得越多，模型越难把新产品放进去。
3. **尺寸、握法和遮挡跟着形态变。** 盒子比滴剂瓶宽得多，握盒的手指包住侧边；条包比瓶子短、薄，捏它的手指更靠拢。把新的握法写出来。
4. **两种形态都做不到的动作，改成最接近的真实动作**，直接写新动作是什么、结束时产品在哪。例如原片挤胶头、抽滴管：写成“指尖捏着未开条包在胸前轻轻晃一下，正面标签朝镜头”。
5. **前后段的状态要连续**，按 [product-actions.md](product-actions.md) 的状态链走：先未开、后已开，同一个镜头里形态前后一致。
6. **撕开发生在镜头外**（用户 2026-10-24：画面里不出现撕条包的动作）。展示、抽出、拿着讲话用**未开条包**（`handheld_photo`）；喝的镜头用**已开条包**（`opened_packet_hand`），一出现就是撕好的。原片一镜到底从取出到服用时，在手开始往嘴边移动的那一刻写一个**镜头切换**：切换前是未开条包的展示，切换后是已开条包贴唇；两张图都给，未开在前。
7. **服用一律闭唇轻抿**（用户 2026-11-11）。原片张嘴、伸舌、往舌头上滴、把胶囊丢进嘴里、嚼软糖时，目标都是：已开条包的平口贴在下唇，合拢的双唇含住袋口轻抿一次，袋身被指尖轻轻压扁，随后手把条包移开，嘴唇合着轻轻咽一下。
8. **逐拍预判模型会照抄什么，再定动作**（用户 2026-11-14：后期补穿帮太多，是提示词和动作设计的问题）。视频参考生成会照抄参考片的姿态、道具轮廓和口型，提示词里一句"平躺""用茶匙"压不住。写每个镜头前对照参考帧问四件事，命中就按 §4.8 改动作，而不是只改措辞：
   - 原物在这一拍**离手并立着**吗（放到台面、长凳、掌心、抽屉里立着）？
   - 原片在这一拍用**勺子**或别的竞品配套道具吗（舀、倒进勺、搅拌、勺放回台面）？
   - 产品在这一拍**被手整个包住或挡住**吗（双手合握、握拳、递接时两手交叠）？
   - 产品在这一拍是**小而远**的吗（逆光远景、全景里只有几十像素）？

### 4.4 每个镜头怎么写

- 每个镜头一行：谁、景别，产品在哪只手或哪个位置、朝向、怎么拿、做什么。
- **@视频1 只管场景、人物外貌、机位、构图和镜头时长，不写“动作照@视频1”“人物动作和节奏照它”**（用户 2026-11-19：这句会让模型反复照搬原视频的动作，连带照搬手里竞品的样子）。拿产品的那只手做什么，逐拍写出来：哪只手（按画面左右写，原片放大核对过）、手在哪、怎么握、产品朝向、动到哪。放慢的单镜头参考片写“@视频1 是这个镜头放慢后的样子，用于镜头时长和人物的位置”。`generate --prepare-only` 和 `shot_regen.py prepare` 遇到这类句子会提示。
- 尺寸写相对关系：条包约一根食指长、比拇指指腹略宽、很薄；纸盒正面约一掌宽，单手握住两侧。
- 物理按现实写，都用正向描述：
  - 条包不在手里时，怎么放按这一镜的原画面和现实物理来设计，不套固定写法：平躺（正面标签朝上，有接触阴影），或斜靠在画面里真实存在的东西上（写明靠在哪、哪里接触）。**原物在这一拍是立着的，就不让条包离手**：整拍写成指尖一直捏着条包（见 §4.8 第 1 条），这批里写了"平躺"仍然竖立的有 5 段（NV0004 G05、NV0015 G04 / G05、NV0054 G05、NV0109 G01），之前 11-11 G11 也一样。
  - 条包在手里：指尖轻捏扁平的边缘，袋身随手指微微弯曲；喝的时候袋身被指尖轻轻压扁。
  - 纸盒立在桌上：底面平贴台面，竖直，正面印刷平整。纸盒在手里：手指包住两个侧面，盒身是直角直边。
- 产品的数量和归属写在素材说明那一行（§3 第 7 条）。

已经验证过的动作对应（编辑模式时期验证，动作设计本身不受模式影响）：

- 手指捏住瓶盖立在桌上 → 从口袋抽出条包，横着放平在桌上
- 一手扶立着的瓶子、一手指瓶 → 条包平躺，一手平放在旁边，另一手食指在标签上轻点
- 双手环抱瓶身展示 → 双手拇指和食指分别轻捏条包上下两端，标签朝向镜头
- 滴管服用 → 单手拇指和食指捏住已开条包的下半部，头自然直立，手从唇侧送入，袋口贴住下唇，合拢的双唇轻抿一次，手把条包降离嘴边
- 一只手抽滴管、另一只手扶瓶 → 一只手指尖捏着未开条包，在原位置轻轻晃一下，正面标签朝镜头
- 一镜到底抽滴管再往嘴里滴 → 中间写一个镜头切换：之前未开条包轻晃展示，之后已开条包贴唇轻抿

- **条包可能被画成背面。** G04 手部特写写了正面标签朝镜头，出来的是背面成分表。
- **参考片里 OCR 读不出的淡水印会被原样生成出来**（G01、G02、G09）。能读出片段的现在会被清掉（§1 第 6 条）；读不出的在生成片上用固定框修补。

## 5. 台词怎么写

- **整段的台词和口型由模型重新生成、一起出**（用户 2026-11-11），不分改没改词。本段听得到的每一句都写出来，格式是“称呼台词：“确切英文””，放在它开始的那个镜头后面；称呼用画面里看得出的特征（深绿上衣男士），画外说的写“画外深绿上衣男士台词”，旁白写“画外旁白台词”。`plan` 的模板已经按听写把每一句预填好，逐句对照原片核对。
- **每句只写一次，后面不跟描述**（官方：台词后复述词语、追加语气和动作会诱发字幕；写在别处的可读文字也可能被念出来）。需要区分情绪时写成“称呼台词（情绪）：“……””。听的人写在镜头描述里（“皱眉听着，自然闭口”）。
- **台词密度**：经验值是每 3 秒不超过 8 个词左右。视频参考生成是模型自己排节奏，原片语速很快的段要预先想到台词可能挤不下：审片时用 `words.py --generated` 逐词核对最后一句有没有说完。
- **品牌名单独成句、原词不到 1.3 秒时只写 “LymphLoop.”**，不带 yesnap（编辑模式实测：1.1 秒的空档里 “yesnap LymphLoop.” 被念成含糊的词）。专有名词是生成台词里最容易念错的，审片先核对它。念糊的品牌名在选片时用 `splice --mute-window` 消掉。
- **新句的音节数和停顿跟原句对齐**（11-14 两条片子）：原句 "One scoop, morning and night" 改成 "One packet each morning." 被念成 "One dupe, one packet each morning"（模型按原句的逗号停顿补词）；"A spoon of something" 改成 "A packet" 少了音节，多出来的口型念成含糊词。写成 "One packet, every morning."、"A little packet of something" 这样保留原句的逗号和大致音节数。
- 冲突台词只改冲突词，音节尽量接近原词：Drops → Packets，dropper → packet，capsules / pills / gummies → packets，one scoop → one packet，under your tongue → straight from the pack，chew → sip，<竞品名> → yesnap LymphLoop。用量按 `profile.json → use` 的真实用法改。
- **提示词正文里绝不出现被替换的原词**，只写新词所在的完整句子（编辑模式实测：写了“原来的 Drops 改为 Packets”，模型念成 "Drop-its"）。
- **冲突词在提交前消音**：`generate --prepare-only --mute G##:起-止[,起-止]`（只动音轨），复听实际参考文件确认相邻词完整，这样参考片的声音里也没有旧词。窗口要把旧词从头到尾盖住，宁可碰到相邻词的边，不留旧词的头尾（准备时有提示，见 §4.7）。细节见 [workflow.md](workflow.md) 的改词附录。
- **窗口大小按位置定**（2026-11-13 整批实测）：
  - **旁白改词消整句**（含旧词那一句，前后静音之间）。只消成分词的窄窗口旁白 2/2、前一批 3/5 留成静音；整句消音后 NV0004、NV0035、NV0048、NV0109、NV0113、NV0133、NV0183 的 Dandelion 全部念出。
  - **画内对白旧词在句中、消掉后会和旁边停顿连成 0.8 秒以上空白的，消整句**。"One spoon in water, morning and night" 窄窗口在 NV0040 / NV0024 都没念出 packet，整句消音的 NV0038 一次念全。
  - 句尾的单个替换词（little bottle → little box）可以只消这个词。
- **品牌名**（用户 2026-11-14：念得略偏是小问题，重点在画面）：模型按原词的音节和口型补词（Nuflos → Loops / flute / woop / nap）。写法：
  - 消音窗口盖住 "It's called ___" 整个分句（或品牌名所在的整句），不只盖原品牌名；原品牌名结尾的 s 要整个落在窗口里。
  - 提示词里品牌名只写 "LymphLoop"，**不写音标、斜杠、读音讲解**（11-14 1454 restore：写了 "/ˈlɪmf luːp/" 被念成 "lymph loop slash lymph loop"，写"Lymph 和 Loop 两段连读，末尾闭唇收在 p"引出品牌名重复）。`prepare` 遇到音标、斜杠读音直接拒绝。
  - 同片同角色另有一处念对的品牌名时，记下时间备用。
  - 审片用 Whisper large-v3（不加提示词）和 Gemini 盲听各听一遍；两者都听成 loops / woop / flute 时按念错处理。

## 6. 审片与本地修补

`review` 检查字幕、改词、残留文字和纸盒几何。Claude 对照原片、实际参考与生成结果逐镜头看。视频参考生成是整段重新生成，除了产品还要看这几样：

- **和前后原片镜头接不接得上**：人物的脸、发型、服装、背景、色调和原片一致吗？成片里这一段两头接的是原片镜头，差别大的地方记进缺陷。
- **镜头数量和顺序**和参考片一致吗？有没有多出镜头、少了镜头、镜头被拉长缩短？
- **产品**：每个写到它的镜头里都是目标产品吗，形态、大小、握法对吗？没写到它的镜头里有没有多出来？
- **台词**：`words.py --generated` 逐词核对，每句都说了、说完了、品牌名念对了；口型看片判断。
- **结尾**：输出比本段长（整数秒），`select` 默认只取段长；最后一句没说完时用 `--clip-out` 放长。

**声音**：选用的画面带着它自己生成的声音，不拆开（`select` 默认 `--sound candidate`，不会自动换原声）。`sound_drift` 是生成的说话声相对原片的时间偏移，视频参考生成的口型是重新生成的，所以它只说明台词的时间位置变没变，口型对不对要看片。看得到说话嘴的地方只用同一文件同一时刻的自带声音（用户 2026-11-21："这种带有口型同步的替换段，不论有没有改口播，都应该要用生成段自带的音频"）；`--sound source`、`splice --audio/--audio-window` 只用于看不到嘴的画面，要 `--no-mouth` 标出。声音和它自己的嘴对不上：补做那一镜（`lip_sync`）。

**后期修补是兜底**（用户 2026-11-14）：每处修补在选片 note 里写明属于 §4.8 哪一类照抄，同类镜头在后面的片子里改动作设计，不靠修补重复解决。

**禁止贴图补救生成段**（用户 2026-11-14："skill 必须要禁止使用贴图来补救生成成片"）。生成画面里的穿帮只能用整帧级的办法处理：
- 允许：`select --clip-in/--clip-out` 裁掉补尾、去掉几个闪帧（每段最多比原段短 0.5 秒，见下一条）；借同一素材兄弟片的整镜（画面和同期声一起，接在硬切上，记 `local_splice` 注明来源）；`splice --mute-window` / `--audio-window` 消音、补音；`select` 自动去残留字幕；`region_inpaint.py :purple`（字幕）和 `:ink`（道具上的旧品牌字）。
- 禁止：贴色块 / 色条、贴产品图、跟踪贴片、从别的帧或别的片子抠一块贴进来、局部调色把竞品染成产品色、用 LaMa / inpaint 把画面里的产品或道具（瓶子、勺子、多出来的条包、糊掉的手）抹掉或改画；**把生成画面放大裁切来躲开穿帮**（11-14 NV0501 G01、NV0481 G09、NV0454 G02、NV0452 G05：放大后说话的人、递东西的动作被裁出画面，等于删了原片内容）；**拿原片画面放大重取景、或裁切别段的生成画面去顶替生成镜头**（11-14 NV0560 G01 车边交接换成原片约 6 倍放大的头部、中间插 0.7 秒 G02 生成条包镜的裁切；G05 末镜两人宽景换成一人头部放大）；自己写 ffmpeg 脚本拼生成段。`region_inpaint.py` 在生成段帧范围里拒绝整框填充；`recut` 拒绝不是账本登记结果（及 select / captions 自动衍生版本）的选片，`splice` 只收本 RUN 生成结果和原片整帧。
- **不许删原片内容**（用户 2026-11-14："codex 会擅自把原片的一些段落给删掉，直接不做，这是不允许的"）：不剪掉镜头、不剪掉整句台词、不把要换的段落留着不做、不把段剪短来躲开穿帮。成片里原片的每个镜头和每句台词都要在，要么是原片，要么是换好的生成段。`recut` 会拒绝比原段短 0.5 秒以上的选片，只有用户明确同意删某段时才加 `--user-approved-cut G##`。
- 借镜救不了的穿帮（产品变形、残留、缺词、念错），写进交付说明并报告用户，由用户决定是否付费重新生成这一段。
- 产品变形和穿帮的根本解法在生成前：按 §4.2 第 8 条和 §4.8 设计动作、处理参考片（中远景竞品真去掉、不裁人物）、写清数量和外观。
- 原片画面不在此列：参考片和保留原片镜头的去字幕、去水印，`brand` 盖 LYMPHLOOP，原片镜头里残留的小瓶照旧处理。

**生成结果一律选用**（用户 2026-11-11）：审片只记录缺陷与时间码（`select` 自动带上 `defects`），能用免费的本地手段处理的就处理（裁掉补尾和几个坏帧（每段不超过 0.5 秒）、`select` 自动去字幕、`splice` 用兄弟片同一镜整镜顶替（不剪掉镜头）、`splice --mute-window` 消掉念错的尾音、`region_inpaint.py :ink` 抹掉道具上的旧字；缺词和品牌名尾音的修法见 §4.7 的表；画面残留不贴图，见上一段），其余写进交付说明。不再自行付费生成第二次，需要时报告用户决定。
